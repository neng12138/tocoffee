## D3 决策与偏差

- 不引入 Passport：P0 只有两种 Bearer JWT，直接用 `@nestjs/jwt` 的 `verifyAsync` 更少依赖、行为更可控。
- 限流先用进程内 Map，满足单实例本地演示；多实例/生产需换 Redis，已记风险。
- 验证码先 mock：`AUTH_DEV_MODE=true` 时返回 `devCode`；生产必须关闭该开关并接入短信服务。
- 员工改密接口不在原计划 5.1 的显式清单里，但 owner 需要能改 seed 默认密码，P0 先补上；新密码要求至少 8 位且包含字母和数字。
- 菜单保留 `SOLD_OUT` 商品（置灰可看），排除 `OFF_SHELF`；下架选项不下发，避免前端展示不可选规格。
- `business_hours` 的 `day` 严格要求数字 1–7，不再接受字符串数字；避免 JSON 脏数据被静默修正。
- `expiresIn` 来自环境变量时是普通 string，`@nestjs/jwt` 要求 `ms.StringValue`，在 service 内做了显式类型收窄；当时运行值 `7d` / `12h`，D5 收尾后员工改为 `24h`。
- `uploads/` 仍未做静态托管，菜单图片 URL 目前会 404；计划 D5 接上传时一起解决。
