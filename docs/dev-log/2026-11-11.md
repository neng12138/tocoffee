# 2026-11-11 开发日志（D10–D13）

## 今日目标

- [x] `OrderExpiryJob`：每分钟关闭支付超时的待支付订单
- [x] `ScheduledOrderReleaseJob`：每分钟释放到 `release_at` 的预约单
- [x] `NoShowJob`：每日 23:59（Asia/Shanghai）关闭当日未取的 `READY` 订单
- [x] 任务幂等/条件更新，多实例安全
- [x] e2e 覆盖重复执行、提前释放、未来订单、跨日补跑

## 完成内容

- 引入 `@nestjs/schedule@12.0.3`，`AppModule` 注册 `ScheduleModule.forRoot()` 和 `JobsModule`。
- `ScheduledOrderReleaseJob`：
  - 扫描 `PAID + SCHEDULED + released_at IS NULL + release_at <= now`。
  - 条件更新 `released_at`，同事务写 `SYSTEM` 事件「预约单已释放，进入待接单」。
  - 多实例同时跑时，只有一个实例能更新成功，另一个跳过。
- `OrderExpiryJob`：
  - 扫描 `PENDING_PAYMENT + expires_at <= now`。
  - 条件更新为 `CANCELED`，写 `canceledAt`、`cancelReason=支付超时自动取消`，并写 `SYSTEM` 事件。
- `NoShowJob`：
  - 23:59 处理当日 `READY`，改为 `NO_SHOW`，写 `noShowAt` 和 `SYSTEM` 事件。
  - 自动补处理更早营业日仍停留在 `READY` 的订单；未来营业日不处理。
  - 不自动退款，保留后续手动退款能力。
- `JobsScheduler`：每分钟释放/过期任务，每日 23:59 `NO_SHOW` 任务；任务异常只记日志，不中断应用。
- 批量处理每批 200 单，条件更新保证同一订单只处理一次。

## 决策与偏差

- 决策：用 `@nestjs/schedule` 的 `@Cron`；依赖选 `12.0.3`，因为 6.x peer 只支持 Nest 10/11，和当前 Nest 12 不兼容。
- 决策：三个 job 的方法都接受可选 `now`，方便测试和多实例补跑；生产由定时器传当前时间。
- 决策：预约释放写 `PAID → PAID` 事件，表示状态未变、只是释放进入队列。
- 决策：`NO_SHOW` 只处理 `READY`，不自动退款，符合设计 8.6。
- 与设计/计划不一致：无。
- 已更新文档：README、notes、PROGRESS、本日志。

## 阻塞与风险

- `NO_SHOW` 依赖应用在 23:59 存活；如果整晚停机，次日 23:59 会补处理前一天 `READY`，不会遗漏，但会晚一天。
- 任务使用条件更新保证幂等；多实例下不会重复写事件，但没有额外的分布式锁。
- 首次部署执行时，会清理开发库里历史遗留的过期待支付单和旧 `READY` 单，属于预期行为。
